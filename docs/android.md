# 安卓真机辅助后端

网页端继续使用原来的 `douyin doctor/sync/run/reply`。安卓明确通过 `douyin android` 选择，
不因为网页失败而自动切换，不会继承网页的自动回复开关。

本入口整合了真机实验通过的操作步骤；尚无可靠的服务端会话/消息 ID，因此属于人工辅助后端，
不是网页版同步和自动回复的完整替代。可用 `open --execute` 从手机桌面/其他 App 切回抖音；
可按配置昵称进入已由人确认的唯一互关私聊，打开会话会标记已读。

## 准备

- 已登录 Echo 专用账号的安卓手机；保持解锁、亮屏。实验环境为小米 13、Android 16、
  抖音 40.4.0。资源 ID 与该版本绑定，其他版本须重新验收，不能只修改版本配置跳过检查。
- USB 数据线、Android SDK Platform Tools（`adb`）。普通 USB 调试必须授权这台电脑。
  小米设备还需要由人开启“USB 安装”和“USB 调试（安全设置）”。登录、验证码、系统授权都由人处理。
- 本机 Appium 和已安装的 UiAutomator2 驱动、匹配的手机服务 APK；实验版本是
  Appium 3.8.0、UiAutomator2 8.7.0。该代码连接已有服务，不自动安装或重置手机。
- `ffmpeg`、`ffprobe` 在 PATH 中，供导出/导入媒体校验使用。纯截屏无需第三方平台、模型或新 Python 包。
- 结束同一账号的网页 `run`/`sync --watch`，再操作安卓；跨进程锁会拒绝同时运行。

在装好工具、驱动和 APK 的环境中，先单独检查设备，再单独启动 Appium：

```powershell
adb devices
```

```powershell
appium --address 127.0.0.1 --port 4725 --log-level error --log-no-colors
```

如果使用实验时的本地安装，沿用该安装的 `APPIUM_HOME` 和 `appium.cmd` 路径。
不要打开 Appium debug 日志，日志可能包含屏幕或输入信息。项目只允许连接本机无凭据的 HTTP 地址。

在现有配置中添加下面一段；不要覆盖文件内已有的模型配置：

```toml
[douyin.android]
enabled = true
udid = "你的设备序列号"
adb = "adb"
appium_url = "http://127.0.0.1:4725"
allow_send = false
auto_reply = "dry_run"
tested_version = "40.4.0"
```

```powershell
uv run douyin android doctor
```

`doctor` 检查连接、版本和前台页面，不验证账号身份或互关关系。请人工确认登录的是专用账号。
所有真实账号命令分别运行；出现验证码/风控立即停止并冻结，不能换参数连续尝试。

## 启动与页面定位

`uv run douyin android inspect` 只读识别当前页面，输出类型和结构证据，不输出页面原文。
`uv run douyin android open` 默认 dry_run；加 `--execute` 才启动/切回抖音，一次运行只激活一次，
最多等待 10 秒。抖音已在前台则保留当前页面，无法识别时明确返回 `unknown`。
这两个入口允许从手机桌面或其他 App 开始；现有读写/回复入口仍严格要求抖音前台。

识别规则覆盖桌面、外部 App、系统遮挡、私聊、作品视频/图集、清屏视频/图集、
分享面板和图片保存页；完整底栏结合顶部频道/工具栏识别首页与消息列表。
40.4.0 底栏没有有效选中态：朋友页使用专用“添加朋友”入口，自己的主页使用
“编辑主页”及作品/日常/收藏/喜欢分栏联合识别；两者都要求完整底栏。
缺少结构证据（包括搜索、设置、直播、他人主页等未建规则页面）返回 `unknown`，不会猜测或盲点。
规则的离线覆盖不代表所有页面都经过真机验收。
锁屏、登录、验证码或权限弹窗需人工处理；不自动解锁、登录、关闭弹窗或选择私聊，不调用模型。
上述命令仍受安卓 enabled、设备/版本检查、账号冻结、pending 和平台锁约束。

未支持的页面和其他版本仍须验收，不能推定所有位置都能识别。

## 当前会话读取与单条发送

### 长驻监控

`douyin android monitor --confirm-current-thread --generate --allow-send` 使用
`[douyin.android]` 的 `thread_name`、`self_name` 精确昵称及 `monitor_interval_s`（默认7200秒，2小时）。
默认 `monitor_trigger="notification"`：通知触发为主，定时检查补漏；`poll` 可恢复仅定时模式。
手机安装仓库 `android/notification-bridge` 构建的 Echo 通知桥，并由用户手动授予通知使用权。
通知桥没有网络权限，仅筛选抖音的非汇总、非明确群聊通知，按精确标题或 MessagingStyle
末条发送人匹配配置昵称。只向 USB ADB 转发连接传递更新计数，不传送正文；
手机本地抽象套接字检查调用者为 shell/root，其他 App 不可连接；电脑端动态端口仅用于本机 ADB。
通知更新去重、2秒合并，处理期间到达的事件保留到下一轮，UI校验与原基线继续决定是否有新消息。
每轮结束返回桌面，减少聊天前台抑制通知；不会自动解锁。未知/隐藏/汇总通知靠定时补漏。
通知权限撤销、桥断连或协议异常会停止，不自动重启；启动建立新基线，不追补停机期间消息。
通知桥每15秒发心跳，电脑容忍最多60秒静默；连接结束或无效协议仍立即停止。
没有通知也会按补漏间隔检查，通知不会推迟补漏截止时间。通知格式和后台保活需按真机验收。

用户可修改配置文件，或用下面命令安全局部修改（不会改密钥、昵称或发送开关）：

```powershell
uv run douyin android monitor-config --interval-minutes 120
# 例如改成4小时
uv run douyin android monitor-config --interval-minutes 240
```

允许1秒到7天，修改运行中配置会停止监控，重新启动后生效。手机端构建不下载依赖：

```powershell
./android/notification-bridge/build.ps1
adb -s <设备序列号> install -r dist/notification-bridge/echo-notification-bridge.apk
```

构建需要本机 JDK、Android SDK platform/build-tools 36；使用本机开发签名，APK和签名文件在忽略的dist目录。
安装后打开手机上的 Echo 通知桥，点击“打开通知使用权设置”，手动允许该应用。
用 `uv run douyin android notification-check --seconds 30` 单独验证连接和目标通知计数，
此命令不启动 Appium、不打开私聊、不调用模型、不发送消息；由对端产生新消息才能验收真实匹配。
加 `--until-update` 可在首次目标更新后立即结束；诊断输出只含抖音通知分类计数，不含正文。
手机通知桥首页显示授权、监听、电脑连接和目标配置状态，以及符合条件的通知历史（时间、标题、正文）。
首次通过电脑 `notification-check` 或通知模式 `monitor` 配置目标后，目标哈希保存在手机应用内，
断开电脑仍可记录，应用重启后保留。更换目标自动清空旧历史；不会开启电脑自动回复。
历史仅存应用私有且不备份的目录，按通知时间倒序，最多100条、保留7天（展示、写入和启动时清理过期记录）；标题/正文分别最多256/4000字符。
相同通知重复回调去重，同一通知的新内容/时间更新单独保留。首页自动刷新，支持手动刷新与确认清空。
清空不移除抖音消息或系统通知，重连也不会重新显示已清空的相同通知；新的更新仍会记录。
接入时仍在通知栏的匹配通知标记为“接入时已有通知”，仅入历史，不增加触发计数。
已消失的通知、未发布或隐藏的正文无法恢复，历史不是完整聊天记录，也不用于自动回复或补发。
历史页面禁用截图和最近任务预览；未增加网络、存储或发送权限。撤销通知使用权停止采集，已有历史可手动清空。
存储故障会在首页提示，记录可能仅在内存中保留；历史不出现在电脑诊断、审计或模型输入中。
本机验收：安装并由用户授予通知使用权后，已有目标通知匹配及一次实时新增通知命中通过。
曾出现一次流断连；增大心跳容忍到60秒后实时复验通过，长期后台稳定性仍待验收。
小米真机更新APK后曾保留授权但不绑定服务；显式打开应用会请求恢复已有绑定，
若仍未恢复，需要用户在系统设置关闭后重新开启通知使用权；不会自动切换权限。
真实通知→自动导航→模型→实发的整轮仍待验收，当前没有重启自动回复后台。
启动前确认专用账号及配置中的唯一互关私聊。启动及每次轮询前自动切回抖音，
从已识别的首页/朋友/个人主页进入消息列表，按精确昵称定位已有会话，再核对标题、双方头像和底部。
已有其他私聊无草稿时可返回；作品详情/清屏/分享面板有界返回。未知页面、遮挡或草稿不盲点。
列表只查已有会话，不点顶部推荐头像；目标不在当前屏时最多向上6次、向下10次查找，
重名、群聊标记、部分遮挡、未找到或布局未稳定即停。昵称与互关关系依赖用户事先确认，
不是稳定平台身份；不支持群聊。初始可见记录须包含双方头像和消息。
可单独用 `douyin android enter-thread --confirm-mutual` 验证导航，不生成或发送。
启动只建立基线，不补回历史。正常空闲、成功回复、模型选择不回复后继续监听，不限总时长/次数。
每批新增消息最多一次回复决策和一条发送，发送使用独立操作编号；护栏与限额继续生效。
休息时段等待，结束后下个轮询恢复；等待期间每30秒检查开关，变更配置需重启。
`--media` 显式允许新分享解析及理解；未启用或多张新分享时保留积压并暂缓，不猜内容。
频率护栏阻止时保留积压，后续轮询再检查；已生成但内容被拦截不重复付费生成。
出现登录/风控、锁屏、断连、人工草稿/己方新消息、身份或消息衔接不明、发送不确定时停止，
不会自动重启或重发。保持手机解锁亮屏，可离开私聊或切换 App，下一轮自动返回；
恢复保留原基线、不将积压当历史跳过。检查间隔内消息超出可见历史可能导致无法衔接而停止。
不支持跨会话、改名自动追踪或重启补收。原 `android run` 仍为有界单轮入口。

## 有界文本自动回复

`douyin android run` 监听人工已打开的唯一互关私聊，使用现有 `[llm.reply]`、人设和近况。
它最多做一次模型决策、发送一条消息，然后退出；SDK 网络重试关闭。默认等待最多 300 秒，没有新消息就退出。
不会自动打开别的会话，也不会自行续跑。2026-10-01 单会话分步真机验收中，完成一次模型调用、
一条实际回复和己方 UI 回显校验，没有重发；没有独立对端回执。
现场修复顶部旧气泡裁切、连续消息隐藏头像，以及复用同一份多段草稿合并发送的问题。
最后一条发送复用了此前被格式限制拦下的模型草稿，未再调用模型；最终命令的不中断全程运行和更多样本仍待验收。

先打开聊天底部，确保可见记录同时有双方的头像和文本消息，清空人工草稿。
确认昵称、账号和互关关系；运行期间不要操作手机或从其他端回复。只观察新文本，不调用模型、不输入：

```powershell
uv run douyin android run --thread "对方精确昵称" --self-name "自己的精确昵称" --confirm-current-thread
```

添加 `--generate` 才允许最多一次回复模型调用（可能付费）；保持 `auto_reply = "dry_run"`
时仅生成草稿。要实际自动发送，还需把 `[douyin.android]` 的 `auto_reply` 设为 `"on"`、
`allow_send` 设为 `true`，命令加 `--generate --allow-send`。`[douyin].auto_reply = "off"`
仍会停止安卓自动回复。命令只能单独运行；批量/重复真实验收须先确认数量。

启动时可见历史只作基线，不回复旧消息。新消息必须能通过头像标签、左右方位和气泡位置唯一归属，
并与上一屏形成唯一的顺序衔接；连续气泡隐藏头像时，仅接受紧接同一发送方且消息容器列与已确认头像行一致的气泡。
新消息挤出顶部头像时，仅排除紧贴滚动容器顶边的旧气泡残片。
输入键盘缩短历史时，仅接受至少两条、唯一匹配的原序列尾部。重复消息歧义、无法衔接的滚动、切换会话、己方新消息、人工草稿、
休息时段、冻结或配置变化都停止。昵称只用于本次人工确认，不冒充稳定账号或会话 ID。
同样的可见屏幕可能隐藏相同文本的新消息，当前方案宁可遗漏、不猜测增量。
重启会重新建立基线，不追补关机期间消息；不能替代完整、长期、无人值守的同步。

生成前检查对象与频率，允许数量内的模型短句用空格合并成一个气泡，再检查总长度、内容、置信度和单行限制；
超出允许条数不合并、不发送。发送前再次核对消息和配置。
与人工发送共用 pending 防重发和全账号限额，异常冻结等待人工处理；UI 回显还必须属于己方。
dry_run 草稿与决策保存在本地回复记录，审计只记录哈希、模型和状态。

未启用 `--media` 时，新分享仍返回 `deferred`。未选择分析的历史分享仅作为“内容未知”的
占位符，不以标题猜内容；要求模型在新问题依赖历史分享时不回复。纯截屏不被当成完整视频。

## 视频、图集理解后回复

对新收到的分享，用上述 `run` 命令加 `--generate --media`。一次只处理一张新作品卡片；
同时出现多张新分享则暂缓，不自行扩大预算。发送仍需安卓两个配置开关及 `--allow-send`。
`--media` 允许将本次从官方卡片复制的作品链接提交给 KuKuTool，并允许该视频最多一次整段音轨转写、
一次媒体理解和一次回复生成。图集不转写音乐。失败不自动重试模型，批量处理先确认数量。

历史作品需要明确选择，不会因为重新启动监听而补回旧消息。先列出当前对方的分享；如需往上翻一屏：

```powershell
uv run douyin android list-shares --thread "对方精确昵称" --self-name "自己的精确昵称" --older-pages 1
```

返回卡片指纹 `card_hash`（仅是本地界面指纹，不是平台 ID）。保持该卡片可见，然后先检查：

```powershell
uv run douyin android reply-share --thread "对方精确昵称" --self-name "自己的精确昵称" --card-hash "返回的指纹" --confirm-history
```

默认只校验，不解析、不调用模型、不输入。添加 `--generate` 才解析并生成草稿；
再加 `--allow-send` 且配置已开启，才实际发送一条。该命令会在指定私聊中打开该作品、
复制链接、返回聊天并滚动到底部，整个过程中不操作其他会话。

绑定检查包括：对方头像与卡片唯一对应、官方详情类型/标题、原生视频总时长或图集连续页码、

## 纯截屏：图集

在手机打开目标图集，长按进入“清屏播放”，暂停自动播放，核对总页数。
下面的 11 是示例，应改成实际页数：

```powershell
uv run douyin android capture-gallery --pages 11
```

只有分页按钮数量和指定值一致才开始。逐页点击、等待、截图，保存 `page-001.png` 等和 `media.json`。
真实重复页不会因图片哈希相同而被删除。当前页选中态尚无可靠通用检测，所以记录 `requested_page`，
并保留 `page_verified=false`、`complete=false`，需要人工逐页检查画面。长图细节、动态图片和音频不在此结果中。

## 纯截屏：视频

在手机打开目标视频，核对总时长，进入清屏模式，设为 **1.0 倍速并暂停**。例如总长约 81 秒：

```powershell
uv run douyin android capture-video --duration 81 --interval 1
```

程序播放并等待两次进度回绕，保存中间完整一轮的采样证据，通常运行约一至两倍视频长度。
不会按固定帧数提前截断；超过时限会留下部分结果。`media.json` 记录每张截图调用开始/结束时刻、
读取的 UI 进度、循环区间、实际采样间隔上界；`interval` 是目标节奏，不是截图覆盖保证。
正常结束暂停视频；发现风控、失联或中断时立即停止 UI 操作，可能需要人手动暂停。

所有截屏视频均标记无音频、无精确首尾、无精确帧时刻、`complete=false`。不能把它当成已经听完、
看完的视频，也不会直接进入自动回复流水线。短暂画面可能遗漏，应根据实际间隔和内容密度补采。

## 原生导出和第三方解析结果

允许官方保存的图集：在手机进入该作品的“保存本地 → 选择图片保存”页面，然后运行：

```powershell
uv run douyin android export-gallery --pages 11
```

此操作会全选保存到手机相册。只查询本次新增的 `Pictures/douyin/share_*` 文件；新增数量不符即停止，
不扫描个人相册，不删手机文件。不要同时在手机保存其他作品。导出按真实文件头识别格式，例如
扩展名 `.png` 的 WebP；使用 ffprobe 与 ffmpeg 全量解码验证。MediaStore 顺序不代表作品原始顺序，
默认不声称顺序已确认，官方导出可能带水印。

无法官方保存的作品可使用 [KuKuTool](https://dy.kukutool.com/) 网页自动解析。
该命令使用本机可见 Chrome，与抖音登录 profile 隔离，不需要连接手机或打开安卓 enabled 开关。
先检查参数（不打开浏览器、不提交链接）：

```powershell
uv run douyin android parse-media "https://v.douyin.com/作品短码/" --kind video
```

确认向该第三方提交这一个作品链接后，加 `--execute`：

```powershell
uv run douyin android parse-media "https://v.douyin.com/作品短码/" --kind video --expected-title "作品标题" --execute
```

只接受单个作品 URL，不接受整段分享文案；提交前去掉查询追踪参数。`--expected-title` 可选，填写后
结果必须包含该标题才下载。默认使用网页视频元素提供的清晰度，最终尺寸与时长以 ffprobe 为准。
图集用 `--kind gallery --count N`，按结果页的图片编号取齐 N 张；看到视频时不会把封面当图集。
一次命令只处理一个作品，批量作品应先告知数量并征得同意。

程序关闭已识别的普通广告、填写链接、点击一次解析，从结果页公开媒体元素取 URL，下载后验证
文件长度、格式及全量解码。仅允许指定媒体 CDN 的 HTTPS 地址，并检查重定向和公开 DNS；每个文件
默认最多 200 MB，解析/单文件下载默认各 90 秒（`--max-mb`、`--timeout` 可调整）。
不会携带抖音 Cookie、读取剪贴板或逆向调用网站内部解析接口。

网页失败、媒体域名变化或需要人工验证时，可人工完成下载，再走现有文件导入：

```powershell

```

只向第三方提供该作品分享链接；不要上传账号凭据或聊天记录。登录、验证码或付费步骤交给人。
没有接入未验证的第三方 API。显式执行 parse-media --execute、reply-share --generate 或
run --generate --media 才会提交作品链接；导入本身不联网、不调用模型。
图集可按原始顺序传入多个文件，指定 `--kind gallery --count N --order-confirmed`；官方手工导出用
